# Verdant · 番茄温室环境监测与智能预警平台

真实LoRaWAN历史数据回放、GRU未来30分钟预测、分层预警、证据增强RAG与人工确认后的模拟事件执行。前端为浅色透明磨砂玻璃风格，显示两个真实温室的46个节点的相对布局与读数。

## 本机使用

项目唯一仓库：`D:\project\选修课\无线传感器\greenhouse-platform`。

1. 双击 `启动系统.cmd`（或运行 `scripts/start.ps1`）。
2. 打开 http://127.0.0.1:8765 。只绑定本机地址，不默认暴露到局域网。
3. 首次运行如未导入，在“数据与模型”点击“校验并导入数据”。导入依赖上级目录中的`公开数据/Greenhouse-1.xlsx`和`Greenhouse-2.xlsx`，在右上温室选择中分别导入。
4. 同页点击“训练并激活GRU”，查看真实任务进度。默认12轮CPU训练，使用部署后前70天及最多10个训练覆盖良好节点，按共同时间轴60/20/20切分。
5. 回放时间可选择 `2020-06-25 13:45`，节点 `AF34` 适合查看已留出的预测窗口。部分节点如AF16在该时段存在缺口，暂停预测属于预期行为。
6. 在预警页选择事件，写记录，依次“AI获取建议或自行选动作→确认事件→执行动作→复看并关闭”。没有人工确认不能执行。
7. 助手页选择节点提问，查看中文读数、预测趋势表和引用资料；检索得分仅维护员可见。API失败时明确显示本地证据模板及降级原因。

首次安装可运行 `scripts/setup.ps1`。需Python3.11+、Node22+。安装会创建项目私有`.venv`，可复用本机已有CPU版PyTorch；前端依赖仅在`frontend/node_modules`。正常运行直接使用构建好的本地资源，无需连接CDN。

## 功能与实现

- **数据**：真实46节点、两处温室分别管理、源时间、温湿度、RSSI/SNR；MD5校验、幂等导入、质量标记、部署前数据剔除。
- **回放**：播放/暂停、5分钟步进、1–1800倍速、任意有效时间跳转；时间后跳创建新会话，保留原事件。
- **GRU**：24×6输入，隐藏32，Linear(32,12)，6×2输出；因果窗口、最多前填1步、真实有效目标MSE、训练段标准化、时间隔离和早停。
- **规则**：当前连续偏离、未来连续偏离、节点数据质量分别提示；同节点/类型合并，参考范围可配置。
- **RAG**：术语扩展 → 中文BM25 + 字符n-gram TF-IDF余弦 → RRF融合 → MMR去重 → 结构化实时证据 + DeepSeek → 引用ID校验。是实际本地检索，不是单纯把问题发给模型；不冒充神经嵌入或交叉编码器。
- **执行**：确认状态校验、唯一command_id、事务幂等、模拟通风/开窗/遮阳、回执日志；环境读数永不被模拟动作改写。
- **UI**：总览、节点与趋势、预测、预警处理、助手、环境参数和数据模型，按角色显示，支持窄屏布局。
- **无线关联**：真实原始LoRaWAN采集信息与网关后发布订阅链路。默认使用本地消息总线；可选MQTT适配器与Mosquitto。不模拟无线物理信道。

## 项目结构

```text
backend/       FastAPI、SQLite、数据导入、GRU、预警、RAG、虚拟执行器
frontend/      React + TypeScript + Vite + ECharts
docs/          先行系统设计、黑白标准设计图及Mermaid源码
scripts/       安装、启动、数据准备和浏览器检查
tests/         核心业务正确性与时间隔离检查
data/          本机SQLite与实际模型权重（不提交）
.env           本机密钥和配置（不提交）
```

API文档：http://127.0.0.1:8765/docs 。数据库DDL见 `backend/schema.sql`。设计方案见 `docs/系统设计方案.md`；设计资料单独存放在上级“系统设计资料”文件夹，不作为系统页面。三张图为标准黑白图，`.mmd`是可编辑源，`.svg`是矢量图，`.png`便于查看。

## 开发

后端：`.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8765`。

前端：进入`frontend`执行`npm ci`和`npm run dev`；Vite代理API到8765。生产构建`npm run build`后重启后端即可同端口访问。

检查：`.venv/Scripts/python.exe -m unittest discover -s tests -v`，以及`frontend/npm run build`。浏览器脚本用于本机安装了Playwright的开发环境，正常启动不依赖它。

**分支约定**：本地只保留此仓库；每次工作先从`main`新建并切换到功能/修复分支，修改完成并通过相关检查后，提交并合并到`main`，随后推送分支与`main`。不要直接在`main`编辑。项目级`AGENTS.md`记录此规则。

## 数据、密钥和实际边界

源数据：[Zenodo公开记录](https://zenodo.org/records/5793685)，作者Singh R.K.等，CC BY4.0。GH1文件MD5 `4bf157516b3b576abe30550c65ce75d9`；GH2文件MD5 `08901111dce781dbe40904292eb847fd`。本项目不把大体积原数据、SQLite、模型权重或依赖目录上传GitHub。原文件需自行放入配置路径，或者使用上级已有公开数据。

DeepSeek配置从`.env`或环境变量读取，仅后端使用。`DEEPSEEK_MODEL=auto`会通过官方`/models`选择可用模型；可显式指定模型名称。Git仅提供无密钥`.env.example`。助手的引用校验验证引用是否来自提供的证据集，不能等价为证明模型每句话都正确，仍需人工核对。

这是一套无硬件课程系统：原始读数真实、节点画面为布局示意、执行器动作是软件模拟。空气VPD不是病害概率。土壤水分、光照、CO₂、电池和实际执行器状态未由主数据提供，不能伪造。部署到真实温室之前，需新增硬件适配、认证授权、作物参数和设施控制规则。

资料：空气环境与通风依据保留在`backend/knowledge.json`的来源字段；GRU与RAG实际实现细节可从源码与助手检索轨迹核对。


## 登录与角色

首次启动自动创建grower（温室管理员）和operator（系统维护员）两个账号，随机初始密码仅写入`data/初始账号.txt`。温室管理员可监测、预警处理、AI问答及修改环境范围；维护员可导入数据、训练模型、控制历史回放。两种角色由服务端校验，密码以PBKDF2摘要保存，会话Cookie为HttpOnly。

独立交付文件在上级`系统设计资料`：完整方案、三张标准黑白图、Mermaid源文件、逐图详细讲解稿。它们不作为系统业务界面。

界面背景图片来源和使用说明见 docs/图片来源.md。图的可编辑源为Mermaid；可使用Mermaid CLI或编辑器按中性黑白主题重新导出。


## 多温室当前版本

可切换比利时GH1（27节点，625972条记录）与荷兰GH2（19节点，360201条记录），两份XLSX来自公开发布页的两次独立部署。通过scripts/download-datasets.py可下载并核验原文件。GH2示意排列不是原作者未提供的精确位置。GH2有六月少量记录及九月多日共同缺口，保留原始记录；模型以多节点形成覆盖的首日开始选择70天范围，默认展示2020-09-24 13:45及AF57预测。各温室独立回放、参数、预警与GRU权重。

事件页的AI建议经过真实RAG检索、DeepSeek生成、可用动作及引用校验。生成建议不会自动选择、确认或执行动作；管理员自行选择后才可确认和执行。业务界面显示中文字段和单位，不显示JSON。动作名称使用通风、开窗、遮阳；本课程后台仍使用虚拟设备并保留执行模式日志。
