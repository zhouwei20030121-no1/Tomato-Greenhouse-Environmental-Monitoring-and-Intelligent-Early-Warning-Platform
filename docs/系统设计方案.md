# 番茄温室环境监测与智能预警平台：系统设计

设计日期：2026-11-10。作者：周玮（222022325052097）。本设计先于应用代码编写完成，作为开发依据。

## 1. 场景、目标与数据边界

服务对象为番茄温室管理员。用户需要知道：哪个节点附近正在持续偏热或偏湿、未来半小时是否可能继续偏离、提示依据是什么、接下来怎样记录检查和处理。

核心链路：真实记录接入 → 多节点回放 → 温湿度/VPD分析 → GRU短期预测 → 分层预警 → RAG解释 → 人工确认 → 虚拟执行器回执 → 继续观察与关闭事件。

数据使用上期已下载的 `../公开数据/Greenhouse-1.xlsx`，27个LoRaWAN节点AF16–AF42，作者原始文件MD5为4bf157516b3b576abe30550c65ce75d9。保留Date、Time、温度、相对湿度、RSSI、SNR。2020-04-17 06:38前为部署前记录，排除出温室业务数据；时间无时区，不转换为北京时间。缺失、可疑值和原始来源均保留，不随机补造观测。空气VPD为派生值，不等同叶片VPD、病害概率或灌溉量。

软件中的“传感器”是原节点的数据镜像；网关后消息回放与射频传播仿真有区别。模拟通风、开窗、遮阳只更新虚拟设备与命令日志，永不修改历史环境读数。

## 2. 技术架构与开题方案调整

采用 Python/FastAPI + SQLite + PyTorch 后端，React/TypeScript/Vite + ECharts 前端。前后端分离有助实现磨砂玻璃界面、多视图联动和传感器画面，因此将开题中的Streamlit替换为React，其余数据、算法与事件闭环保持一致。

默认本机单用户、127.0.0.1访问。一次构建后由FastAPI提供页面与API，启动无需联网下载前端资源。数据库启用WAL、外键与节点时间索引；耗时任务在线程中执行，不阻塞API。重放只有一个活动时间轴，多个页面读取同一状态。

模块：DataImporter、ReplayService、GatewayService、FeatureService、ForecastService、AlertService、HybridRetriever、EvidenceAssistant、EventService、VirtualActuator。默认使用进程内发布订阅总线；另提供可选MQTT网关适配与Mosquitto配置，未运行代理时界面明确标注“本地消息总线”。

## 5. 数据与算法设计

### 5.1 接入和因果窗口

按节点解析Date+Time、排序、去重。无时间隔离；温度/RH物理可疑值标记为无效，原值不删除。每5分钟采用不晚于当前格点的最新观测；单格最多前填1步，始终保留原始有效掩码；不得将未来观测填入当前窗口。

一个模型窗口为过去24步：T、RH、sin(hour)、cos(hour)、maskT、maskRH，共24×6；输出未来6步×2个T/RH。过去窗口缺失比例超过20%、长缺口或无法得到有效输入时，返回暂停原因。

空气VPD：es(T)=0.6108 exp(17.27T/(T+237.3))，VPD=es(T)(1−RH/100)。逐条有效T/RH计算；预测RH无效时不派生预测VPD。

### 5.2 GRU实现

单层共享GRU(hidden=32) → Linear(32,12) → reshape(6,2)。训练只使用原始有效目标，不用填充值伪造标签。所有节点采用共同时间边界60%训练/20%验证/20%留出；窗口与未来目标不得跨分段，标准化仅拟合训练段。Adam、有效目标MSE、早停和固定随机种子；CPU可运行，先选覆盖良好节点限制训练量，保存权重与实际训练元数据。

未训练/权重失败时仅显示真实曲线和规则提示，不冒充GRU。训练结束后只激活经过实际训练且能重新加载的权重。部署历史回放仅在模型训练/验证边界之后展示模型预测，避免把训练期拟合伪装为未来推理；早于模型可用时间返回说明。

### 5.3 分层预警

环境类：T、RH或VPD连续3个有效5分钟点偏离可配置范围；预测类：未来6步至少连续2步偏离；质量类：陈旧、缺失或可疑值。类型分开，按节点/类型/回放会话合并，初设10分钟冷却。同一格点不会被页面刷新重复累计。30℃仅为教学初值，不声称适用于全部种植阶段。

事件状态：pending → confirmed → executed → observing → closed；执行失败可重试且留日志。确认与执行是单独操作，未确认不能执行。关单需填写记录；时间轴后跳创建新回放会话，既有事件保留且不误触发旧指令。

### 5.4 真正参与处理的RAG

1. 解析问题中的节点、指标、事件和时间，并用白名单查询SQLite生成当前读数/预警/预测证据。
2. 知识片段按标题/小节分块并带来源、版本；为温度、湿度、VPD、通风、信号质量建立术语扩展。
3. 第一支路中文词/字二元组BM25召回，第二支路字符n-gram TF-IDF余弦召回。这是可离线运行的稀疏向量检索，明确不冒充语义嵌入模型。
4. 用RRF融合两份排名，再用MMR去除重复片段，选出不同来源的高相关证据。返回BM25、余弦、融合排名、最终选择，前端可查看。
5. 把结构化观测和知识证据交给DeepSeek生成解释。模型必须使用分配的[E…]/[K…]引用，返回后校验引用ID；不在检索集中的引用不采信，标注修正或降级。
6. 没有相关依据时收敛回答，不生成农业结论；API不可用时用相同证据生成本地模板，并明确显示真实降级原因。大模型不改阈值，不持有直接执行器工具。

该算法不依赖付费嵌入接口即可运行。后续可在Retriever接口增加本地双编码器/交叉编码器，不能把尚未加载的模型宣称已实现。

## 6. API与后台任务

REST `/api`：health、overview、nodes、nodes/{id}/series、forecast、alerts、alerts/{id}/confirm、alerts/{id}/execute、alerts/{id}/close、commands、assistant/ask、knowledge、replay/state、replay/control、settings、data/status、data/import、models、models/train、jobs/{id}、design。

所有变更由POST/PUT完成并校验参数；数据库参数化查询。import/train各自只允许一个活动任务；API提供进度。回放循环每次推进源事件时钟后运行网关和规则，浏览器轮询只读取状态，不产生重复事件。

## 7. 实施次序和完成口径

先完成本文、业务流程图、处理时序图和UML类图；再依次实现数据库/真实导入、监测回放、GRU与预警、事件执行、RAG/DeepSeek、磨砂前端和本机运行入口。
